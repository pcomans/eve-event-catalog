A production catalog change necessarily requires a rebuild; without one, neither the generated tool schema, search results, nor Ajv changes. During a single immutable build they cannot silently take different source data. A dev hot edit can leave pre-edit sessions stale, but that is the already-documented hot-reload hazard, not a new drift mechanism in this patch.

4. **Backwards compatibility:** the branch Zod schema accepts `{}` for both `edgar.filing.new` and `alpaca.order.filled`, and the catalog Ajv schemas for both also validate `{}`. These production calls remain valid.
